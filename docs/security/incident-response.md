# Procedura reagowania na incydenty ARC-XR

**Stan: procedura projektowa.** Repozytorium nie ma zadeklarowanego dyżuru ani skonfigurowanego kanału poufnego zgłaszania.

W razie podejrzenia ujawnienia danych biometrycznych, nagrań, sekretów lub utraty kontroli nad publikacją należy przerwać wyłącznie własne niebezpieczne działania, zabezpieczyć minimalny zestaw dowodów i przekazać sprawę uprawnionemu właścicielowi prywatnym kanałem. Nie ujawniaj szczegółów w otwartym Issue, nie kasuj historii Git i nie zmieniaj uprawnień cudzych systemów bez zgody.

Właściciel ocenia zakres ekspozycji (repo, Pages, cache, artefakty, historyczne commity), wersję i SHA, osoby lub urządzenia objęte incydentem, podstawę prawną, potrzebę rotacji sekretów, ograniczenia dostępu, powiadomienia i naprawy. Każdą naprawę potwierdza rzeczywisty test, a nie samo stwierdzenie o jej ukończeniu.

Jeśli incydent dotyczy bezpieczeństwa eksperymentu w XR, pierwszeństwo ma ochrona uczestników i uruchomienie właściwych procedur instytucjonalnych.

Zobacz [SECURITY.md](../../SECURITY.md) i [model zagrożeń](threat-model.md).
